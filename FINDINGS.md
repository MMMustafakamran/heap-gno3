# Findings — Agno-Angular (Agno Python agent + CopilotKit Angular)
Open doc defects only. Numbers are stable IDs (code cites `FINDINGS.md #N`), so gaps are removed findings. Set carried over from the AG2-Angular harness where the shared Angular pages are identical, each re-checked on Agno 2026-11-13.
Stack: `@copilotkit/angular` 0.6.0 (npm latest; declared ^0.6.0), `@copilotkit/runtime` 1.87.1 (npm latest), `@ag-ui/client` 1.0.4 (npm latest; not in the doc's install step), `@angular/core` 22.1.4, `@angular/cdk` 22.2.6, `zod` 4.5.4, `express` 5.2.1, `tsx` 4.23.13, `@tanstack/ai` 1.2.0, `@tanstack/ai-openai` 1.1.1 (Components and surfaces runtime); agent: `agno` 3.2.0 (AgentOS + AGUI interface, `ag-ui-protocol`, `openai`) + FastAPI on Python 3.13 (uv); Node 26.7.0, npm 11, Windows 11 Pro. Docs: https://docs.copilotkit.ai/angular/agno, plus the Angular tab of https://docs.copilotkit.ai/agno/generative-ui/components* (snapshot 2026-11-13)

## Dev blockers (seen with `ng serve` and normal use of the page)

### [Quickstart](https://docs.copilotkit.ai/angular/agno/quickstart)
**#1 The Agno Angular quickstart never shows an Agno backend or a runtime server.**
- **Doc:** the "Connect the selected agent backend" step renders only a callout ("Configure Copilot Runtime to register this backend as the `default` agent at `/api/copilotkit`. Continue with the selected backend's Copilot Runtime guide …"), with no code. The linked [Copilot Runtime](https://docs.copilotkit.ai/angular/agno/backend/copilot-runtime) page shows only a Next.js `app/api/copilotkit/[[...slug]]/route.ts` with an example `my_agent: new HttpAgent({ url: "http://localhost:8000/" })`: no Agno agent and no standalone Node runtime server for an Angular app. "Run the backend, runtime, and Angular app" says "Start the selected agent backend and Copilot Runtime with the commands from its runtime guide", and no page gives those commands.
- **Result:** following the page gives an Angular chat pointed at `http://localhost:8200/api/copilotkit` with nothing behind it. The Agno agent (`agno.Agent` + `AGUIStream` mounted on FastAPI), the Node runtime server (`CopilotRuntime` + `createCopilotNodeListener`) and the `HttpAgent` binding (from `@ag-ui/client`, not installed by the page) all have to be guessed.
- **Confirmed by harness:** `backend/main.py` (the Agno React quickstart's `Agent` + `AgentOS(interfaces=[AGUI(agent=agent)])`, plus `python-multipart`, which AgentOS needs to start) and `frontend/server.ts` (`HttpAgent` at `http://localhost:8271/agui`) make the chat work ("Yep, I'm here! Fun fact: Benjamin Franklin's famous kite experiment…").

### [A2UI schemas, styling, and recovery](https://docs.copilotkit.ai/angular/agno/guides/a2ui)
**#2 The catalog the page requires is never defined.**
- **Doc:** "A catalog is required: without one, A2UI stays off even when the runtime enables it", then `provideCopilotKit({ runtimeUrl: "/api/copilotkit", a2ui: { catalog: productCatalog, … } })`; `fixedDefinitions` uses `dynamicString` and `satisfies A2UICatalogDefinitions`; the web-components snippet uses `createAngularCatalog`, `ChildListSchema`, `AcmeBadge`, `PanelComponent`; `beautifulCatalog`, `declarativeCatalog`, `fixedCatalog` are referenced, and the Airport/Arrow/AirlineBadge/PriceTag components are never shown.
- **Error:** `error TS2304: Cannot find name 'productCatalog'.` (also `'dynamicString'`, `'A2UICatalogDefinitions'`, `'createAngularCatalog'`, `'AcmeBadge'`, `'PanelComponent'`, `'ChildListSchema'`; `ng serve` type-checks, so the app doesn't build). Without the catalog: `[CopilotKit] The runtime enables A2UI, but no a2ui.catalog is configured, so A2UI stays off.` and nothing renders.

### [Voice and multimodal input](https://docs.copilotkit.ai/angular/agno/guides/voice-multimodal)
**#3 Voice can't be set up: the transcription backend is never shown.**
- **Doc:** "Follow the [Voice backend setup](/angular/agno/guides/voice-multimodal#backend) to add a dedicated Runtime route and transcription service."
- **Result:** the link points to the same page, and there's no `#backend` anchor on it. No route or `transcriptionService` code is shown, so `/info` reports `"audioFileTranscriptionEnabled":false` and the chat has no mic button. Attachments work ("The chart is titled "Quarterly revenue." Q4 comes to 300.").

### [Shared state and agent context](https://docs.copilotkit.ai/angular/agno/guides/shared-state)
**#4 The agent can't read the state the app writes: the page never shows how an Agno agent uses it.**
- **Doc:** "Agent and application both read and write the value | `injectAgentStore` and `agent.setState`", with `WorkspaceComponent.setPriority()` calling `agent.setState({ ...current, priority })`. The page shows no Agno-side code for reading that state.
- **Result:** after "Mark high priority" the workspace shows `Priority: high`, but asked about the priority the agent says it can't see it ("I don't have access to the selected record's fields, so I can't see its priority."). Agno's AGUI interface keeps the client state as `session_state`, but nothing puts it into the model's prompt (`add_session_state_to_context` is off by default), and the page never says so.

### [Sub-agents](https://docs.copilotkit.ai/angular/agno/multi-agent/subagents)
**#5 The sub-agents code can't be run: there is no supervisor agent or server, and the Angular helpers are never defined.**
- **Doc:** "Setting up sub-agents" has no setup steps (the page source carries `<!-- setup skipped: subagents-setup is not bundled for agno -->`). The `src/agents/subagents.py` blocks define `_research_agent`, `_writing_agent`, `_critique_agent`, the `_delegate` helpers and the tool functions `research_agent(run_context, task)` / `writing_agent` / `critique_agent`, but never a supervisor `Agent(tools=[...])` and never an `AgentOS` / `AGUI` app. The Angular snippet calls `readDelegations(...)` and `subAgentRendererConfig(name)`, which are never defined, and is a fragment of a Showcase class (`this.feature === "subagents"`).
- **Result:** the file imports (`uv run python -c "import src.agents.subagents"`: no `supervisor`, no `app`), but nothing serves the sub-agents, so the chat answers from the plain agent and the delegation log stays empty ("No delegations yet.").

### [Native generative UI](https://docs.copilotkit.ai/angular/agno/guides/generative-ui-components) (in-content: linked from Frontend tools and generative UI, and Using the Angular docs)

### [Components and surfaces](https://docs.copilotkit.ai/agno/generative-ui/components) · [Surfaces](https://docs.copilotkit.ai/agno/generative-ui/components/surfaces) · [Catalogs](https://docs.copilotkit.ai/agno/generative-ui/components/catalogs) · [Standard catalog](https://docs.copilotkit.ai/generative-ui/components/standard-catalog) · [State and actions](https://docs.copilotkit.ai/agno/generative-ui/components/state-and-actions) · [Theming](https://docs.copilotkit.ai/agno/generative-ui/components/theming) · [Transports](https://docs.copilotkit.ai/agno/generative-ui/components/transports) · [Markdown mode](https://docs.copilotkit.ai/agno/generative-ui/components/markdown-mode) · [Adopt from A2UI](https://docs.copilotkit.ai/agno/generative-ui/components/from-a2ui) (Angular tab; in-content, announced by the team)
**#14 None of the Angular code on these pages compiles: `@copilotkit/angular/generative-ui` doesn't exist.**
- **Doc:** every Angular tab imports from `@copilotkit/angular/generative-ui`: `import { provideGenerativeUI, standardUI } from "@copilotkit/angular/generative-ui";` (Components step 3, Standard catalog, Markdown mode), `CopilotGenerativeUISurface` (Surfaces), `createGenerativeUI`, `CopilotGenerativeUIChildren`, `GenerativeUIComponentInputs`, `exportA2UICatalog` (Catalogs, Standard catalog, Adopt from A2UI), `connectGenerativeUIState`, `registerGenerativeUIFunction`, `GenerativeUIEventHandler` (State and actions), `GenerativeUITheme` (Theming); Transports shows only `provideGenerativeUI({ ui: standardUI, ... })` calls.
- **Error:** `error TS2307: Cannot find module '@copilotkit/angular/generative-ui' or its corresponding type declarations.` on every page (`npx tsc -p frontend/doc-verbatim/cmp-<page>`). `@copilotkit/angular` 0.6.0 (npm `latest`; no `next` tag, the only other tag is `canary` 0.3.2) exports only `.`, `./a2ui`, `./mcp-apps`, `./styles.css`. The code exists only on CopilotKit `main` (`packages/angular/src/generative-ui/`), unreleased. `ng serve` type-checks, so the app doesn't build with any of it.
- **Result:** without the provider, asking for UI gets plain text or a code block (e.g. "Render a Card with the title Hello" -> "Here's a simple Card component: jsx `<Card title="Hello">…`"), never a rendered component, on all 8 child pages, 3 probe runs each. Same entry point as #6.

**#15 The Components page's "Try it" runtime never answers: its `server.ts` won't start in an Angular app, and its agent fails every run.**
- **Doc:** Angular tab, step 2: "the runtime is a small Node server next to the app. Start it with `npx tsx server.ts`." `server.ts` imports `chat` from `@tanstack/ai` and `openaiText` from `@tanstack/ai-openai`, and the factory calls `return chat({ adapter: openaiText("gpt-6-luna"), messages, systemPrompts: [...], tools, abortController })`. The page shows no Agno agent at all (the agent is a TanStack `BuiltInAgent`), and says "Your agent must pass the run's tools and context to its model, as in step 2" without saying how for Agno.
- **Error:** `Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: No "exports" main defined in …/node_modules/@tanstack/ai/package.json` (`npx tsx server.ts` in an Angular workspace: no `"type": "module"`, and `@tanstack/ai` 1.2.0 / `@tanstack/ai-openai` 1.1.1 export ESM only). Saved as `.mts` (HARNESS), the server starts but every run fails: `RUN_ERROR` "chat() needs a threadId. Pass a non-empty string, for example the id of the conversation." The chat shows the user message and nothing else, no error on screen (3 probe runs).
- **Confirmed by harness:** `frontend/components-runtime.mts` (the `.mts` copy) starts on :8272; a direct AG-UI request gets the same `RUN_ERROR`.

## Minor notes
- #7 Frontend tools: the browser `getWeather` tool fetches `/api/weather?city=…`, an endpoint no page shows; the render-only `registerRenderToolCall` variant assumes a backend `getWeather` tool the page doesn't show either.
- #18 Frontend tools / WebMCP / Human-in-the-loop: none of the Angular pages says an Agno agent needs a `db` on the `Agent` for frontend tools; without one every frontend tool call ends with `ERROR Error running entity: Frontend tool resume requires a database` (backend log) and the chat gets no reply. The fix (`db=SqliteDb(...)`, needs `sqlalchemy[asyncio]`) is only on the Agno React frontend-tools page.
- #9 WebMCP: `searchOrders(status)` is never defined (`error TS2304: Cannot find name 'searchOrders'.`, so `ng serve` won't build until a helper is added). With a helper, the tool registers on `document.modelContext` (Chromium with `WebMCPTesting`).
- #10 Authentication: `readSessionToken`, `sessionToken` and `verifySession` are app-specific placeholders, never defined, and the snippets have no imports. With trivial helpers the `onRequest` hook works (signed out `401 Unauthorized`, signed in a reply).
- #11 Quickstart: the install step doesn't add `@ag-ui/client` (needed for `HttpAgent` in the runtime).
- #13 Inspector: "**[Inspector](/angular/agno/inspector)** is the page to read for what the panes show" links to the page itself.
- #16 Components and surfaces pages: snippets use names they never define or import: `Product` and `./product-row.component` (Surfaces), `MyFallback` (Surfaces), `cartUI`, `Hero`, `appUI`, `fs` (Catalogs), `ProductCard`, `productSchema` (Standard catalog), `CartStore` / `./cart.store` (State and actions), `Airport`, `Arrow` (Adopt from A2UI); `z` and `createGenerativeUI` are not imported in State and actions / Adopt from A2UI; the product-page snippet has no imports. State and actions declares `export const shopUI` twice over two blocks.
- #17 Native generative UI links to the Components and surfaces pages at `/angular/agno/generative-ui/components/*` (Components, Surfaces, Catalogs, State and actions, Theming, Transports, Markdown mode): all 404. The pages exist only under `/agno/...` with the Angular tab; `/agno/generative-ui/components/standard-catalog` redirects to the framework-less `/generative-ui/components/standard-catalog`.
